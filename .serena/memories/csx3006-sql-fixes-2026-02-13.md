## Analysis Summary

### Issue Scope
Scripts 09-14 used incorrect column names that didn't match the authoritative schema defined in `02_create_tables.sql`. Scripts 01-08 (DDL, indexes, views, seed data) were already correct.

### Root Cause
Query/procedure/trigger scripts (09-14) were written using a different naming convention than DDL scripts (01-08). The mismatched assumptions included:

| Schema Correct | Script Used |
|---------------|-------------|
| PK: `id` on all parent tables | PK: `{table}_id` (e.g., `recipe_id`, `user_id`) on parent tables |
| `username`, `first_name`, `last_name` on user | `display_name` (doesn't exist) |
| `category VARCHAR(50)` on recipe | `cuisine VARCHAR(100)` |
| `quantity VARCHAR(50)` on ingredient | `amount` |
| `instruction_text TEXT` on instruction | `description` |
| `display_order INT` on recipe_image | `is_primary INT`, `caption TEXT` (both don't exist) |
| ENUM('Easy','Medium','Hard') | ENUM('easy','medium','hard') (lowercase) |
| status: 'published','pending','rejected' | Incorrectly referenced 'draft' (doesn't exist) |

### Key Pattern
**Parent table PK references:**
- Child tables correctly use FK: `{table}_id` (e.g., `recipe_id`, `user_id`) — NO CHANGE NEEDED
- Parent table queries MUST use PK: `id` — **FIXED**

### Key Column Mappings

| Entity | Schema | Wrong Usage (Fixed) |
|--------|--------|-------------------|
| User display | `username`, `first_name`, `last_name` | `display_name` (doesn't exist) |
| Recipe category | `category VARCHAR(50)` | `cuisine VARCHAR(100)` |
| Recipe difficulty | `ENUM('Easy','Medium','Hard')` | `ENUM('easy','medium','hard')` |
| Ingredient amount | `quantity VARCHAR(50)` | `amount` |
| Instruction text | `instruction_text TEXT` | `description` TEXT (column name collision) |
| Image ordering | `display_order INT` | `is_primary INT` (doesn't exist) |
| Image caption | `None` | `caption TEXT` (doesn't exist) |

### FK vs PK References

**CorrectPattern:**
- Parent tables (SELECT/UPDATE/DELETE): use PK `id`
  - `FROM recipe WHERE id = ?` ✅
  - `FROM user WHERE id = ?` ✅
- Child tables (WHERE clauses): use FK `{table}_id`
  - `FROM recipe_view WHERE recipe_id = ?` ✅
  - `FROM review WHERE recipe_id = ?` ✅
  - `FROM like_record WHERE user_id = ?` ✅
